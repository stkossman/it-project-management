## 2. Власні числа потоку

**Частково: 7 придатних записів із потрібних ≥12; лише 1 продуктова історія
з потрібних ≥2.** Блок D M8 ще не завершений; бракує щонайменше п'яти реальних
завершень, серед них однієї іншої продуктової історії. Спринт 1 відкритий,
Sprint 2 не почався; симуляцію `lr03_sprint_simulation/sprint_log.md` не включено.

| Поле | Значення |
| --- | --- |
| Карток у файлі | 7, без повторного зарахування |
| Із дошки ЛР4 | 6: F-002–F-007, тип other |
| Продуктових | 1: F-013 → S-11; завершення всередині відкритого Sprint 1 |
| Перша / остання done_date | 2026-10-26 / 2026-10-29 |
| Спостережених тижнів | ceil((3 + 1)/7) = 1 |
| Throughput як показник сталого потоку | Очікує достатньої вибірки; відсутність показника не означає 0 |
| Cycle time P50 / P85 | Очікують достатньої вибірки |
| Lead time P85 | Очікує достатньої вибірки |
| Черга: lead P85 − cycle P85 | Очікує достатньої вибірки |

Cycle time = done_date − start_date; lead time = done_date − created_date.
Відсортований поточний ряд cycle time: **0, 0, 0, 0, 0, 0, 0** календарних днів;
ряд lead time такий самий. За nearest-rank для N=7 позиції ceil(0,50×7)=4
і ceil(0,85×7)=6 дали б 0 днів; арифметика поточного неповного зрізу throughput
була б 7/1 = 7,0 картки/тиждень, але це не підтверджує темп продуктового
розроблення і не винесено на дашборд. Після виконання вимог вибірки ці показники
треба перерахувати на всьому файлі: ранги ceil(p×N), throughput = N/ceil((остання
done_date − перша done_date + 1 день)/7), округлення до одного десяткового знака.
Нульова різниця lead/cycle на цих датах не доводить відсутності очікування:
денна точність приховує хвилини роботи, а шість документів і одна історія
не характеризують чергу продукту.

## Перевірка й незавершені вимоги

Очікувані обмеження LR14: `min_rows` (7 < 12) — відсутній реальний обсяг
даних; `FL-4` (1 < 2 історій) — залежність від наступного продуктового
завершення; `FL-5` — денна точність реальних коротких інтервалів, а не підстава
вигадувати довші дати. Після нових завершень додавати їх із доказами та
повторити `python tools/validate.py lr14_metrics`; змістові блоки A/B/C/E/F
підготовлені, D лишається частковим.
