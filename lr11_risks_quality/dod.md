Установлено 2026-10-29 до реалізації першого інкремента. Критерії приймання
описують зміст конкретної історії в ЛР6; цей спільний DoD описує якість її завершення.

## Умови, за яких історія вважається завершеною

- Усі критерії приймання історії з `lr06_backlog/backlog.csv` мають перевірений результат і посилання на доказ у журналі спринта або issue.
- Автоматизовані перевірки зміненої поведінки та важливих помилкових сценаріїв виконано успішно; команда й результат записані в доказі.
- `bun run build` і `bun run typecheck` успішні для поточного коміту застосунку.
- Наскрізний користувацький шлях перевірено в браузері; для зміненого інтерфейсу перевірено вузький екран і клавіатурний доступ.
- Для історії зі станом перевірено повторне читання після перезапуску API; для доступу перевірено відмову без потрібних серверних повноважень.
- Виконавець переглянув diff: немає відомих блокувальних дефектів, секретів, локальних баз або згенерованих файлів; свідомі компроміси внесено в `techdebt.csv`.
- Код опубліковано в окремому репозиторії `stkossman/planning-poker`; журнал спринта або issue містить незмінне посилання на коміт і чесний статус історії.

## Чого DoD свідомо не вимагає

Другого рецензента немає: його review замінено самоперевіркою diff і
відтворюваними тестами. Не встановлено довільного відсотка coverage або
навантажувального тесту для кожної зміни. Якщо навантаження прямо є критерієм
історії, як 25 профілів у S-01, його перевірка обов'язкова саме для цієї історії.
Рішення навчального замовника про приймання релізу не підміняється технічним Done.

## Хто ухвалює відхилення від DoD

PM (Андрій Ставський) записує запит і ціну відхилення в журналі змін та
технічному боргу; до виконання всіх умов історія лишається незавершеною і не
додає SP у velocity. Послаблення приймальних вимог потребує рішення їхнього власника.
