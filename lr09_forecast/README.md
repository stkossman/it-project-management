## 2. Як рахувалася симуляція

Python, стандартна бібліотека; **10 000 незалежних прогонів на сценарій**, seed **20261026**. Окремий Random заново ініціалізується тим самим seed для кожного сценарію. У кожному прогоні однаково ймовірно вибираємо завершені SP одного історичного спринта з поверненням, віднімаємо від залишку й рахуємо спринти до залишку ≤ 0. Результати сортуємо; nearest-rank індекси ceil(0.50×N)−1 та ceil(0.85×N)−1 дають цілі кількості спринтів.

Мінімальний відтворюваний код; приклади викликів нижче використовують **тільки навчальні** дані:

```python
from math import ceil
from random import Random

SEED = 20261026
SIMULATIONS = 10_000


def monte_carlo(points, history):
    if points < 0 or any(value < 0 for value in history):
        raise ValueError("Обсяг і velocity мають бути невід’ємними")
    if points == 0:
        return 0, 0
    if not history or max(history) == 0:
        raise ValueError("Потрібна історія з додатною velocity")

    rng = Random(SEED)
    results = []
    for _ in range(SIMULATIONS):
        remaining = points
        sprints = 0
        while remaining > 0:
            remaining -= rng.choice(history)
            sprints += 1
        results.append(sprints)

    results.sort()
    return (results[ceil(0.50 * SIMULATIONS) - 1],
            results[ceil(0.85 * SIMULATIONS) - 1])


reference = [21, 17, 26, 14, 23, 6, 28, 12, 22, 25, 18, 9]
for history in (reference, reference[:2], reference[4:6]):
    p50, p85 = monte_carlo(220, history)
    print(len(history), p50, p85, p85 - p50)
```

Нульовий результат спринта не вилучаємо з вибірки: він додає спринт без зменшення залишку. Для додатного обсягу порожня або суто нульова історія відхиляється до циклу, бо скінченного прогнозу немає; нульовий обсяг потребує нуля додаткових спринтів. Змішана історія з нулями й додатними значеннями моделюється без штучного обмеження кількості спринтів.

Модель припускає порівнянні спринти, стабільний масштаб SP та репрезентативність минулої пропускної здатності. Незалежне повторне вибирання не моделює черговість залежностей, зміну команди чи новий міграційний обсяг. P85 — перцентиль умовної моделі, не гарантія і не довірчий інтервал точності.

## 3. Дві дати першого релізу

Обидва майбутні сценарії використовуватимуть перевірену власну історію points_done. Позначення: E₁/E₂ — фактичні кінці спринтів 1/2, N — кількість спринтів відповідного перцентиля.

| Сценарій | Обсяг | P50, спринтів | P85, спринтів | P50, дата | P85, дата |
| --- | --- | --- | --- | --- | --- |
| Весь перший реліз | 64 SP за поточними оцінками. | Очікує velocity. | Очікує velocity. | Очікує E₁ і P50. | Очікує E₁ і P85. |
| Залишок після спринта 2 | Сума оцінок незавершених історій REL-1; очікує перевірки Done. | Очікує velocity. | Очікує velocity. | Очікує E₂ і P50. | Очікує E₂ і P85. |

Формули курсу для P50 і P85 окремо:

- Весь реліз: **дата = E₁ + (N − 1) × 14 календарних днів**. Це прогноз повного обсягу від спринта 1, тому один спринт уже враховано його кінцевою датою.
- Залишок: **дата = E₂ + N × 14 календарних днів**. Обсяг визначаємо за ID, які ще не виконали DoD після спринта 2; завершені історії не симулюємо повторно.

Календарні 14 днів у формулах не замінюємо робочими днями CPM. Фактичних E₁/E₂ закритих спринтів, залишку й перцентилів немає; навчальні дати 2025 року та запропонований старт ЛР7 не підставляємо замість них. Збіг двох результатів також не припускаємо без даних. Остаточний етап має заповнити два сценарії forecast.csv, перевірити різницю дат як (P85 − P50) × 14 днів та підготувати до комунікації P85 саме сценарію залишку.

CPM враховує трудомісткість, тривалості, ресурси й залежності базового плану; Monte Carlo вибиратиме фактичну пропускну здатність із наявними в ній затримками. ЛР7 вже показує перевищення 40 робочих днів на 33; чисельно зіставити P85 з обома датами поки неможливо. Навчальний результат для 220 SP не дає третьої дати цього проєкту.

Після отримання даних PM має порівняти P85 залишку з CPM і початковим дедлайном, а причини розбіжностей звірити з блокерами, залежностями та змінами обсягу. За потреби пропонуємо скоротити зручності S-05/S-04 за ЛР6 або явно переглянути строк/ресурси; SC-01–SC-04 залишаються обов'язковими. Міграційний сценарій ЛР8 і непогоджені контракти можуть вимагати переоцінки, тому ні дата roadmap, ні майбутній P85 автоматично не стають зобов'язанням.

Пара B має близькі значення та середню 19 SP, а пара C — середню 14,5 SP і різкий спад до 6; повторне вибирання відтворює саме цю обмежену картину. Тому пари дають суттєво різні прогнози. Вузький або навіть нульовий проміжок P50–P85 у B не доводить точності: дві точки не представляють можливі блокери, а дискретні кількості спринтів можуть дати однакові перцентилі. 10 000 повторів зменшують похибку симуляції, але не замінюють історію; розширення вибірки не зобов'язане завжди розширювати цей проміжок.

Перевірено повторюваність із повторною ініціалізацією seed та незалежною реалізацією накопичення завершених SP через randrange: усі 10 000 кількостей спринтів кожного сценарію збіглися. Додатковий точний підрахунок розподілу сум дав P50/P85 = 12/14, 12/12 та 15/18. Для C точна ймовірність завершити за 15 спринтів дорівнює 0,5, але в заданому Monte Carlo завершили 4979/10 000 = 0,4979; nearest-rank P50 тому дорівнює **16**, а не 15. Таблиця відображає саме обов'язкові скінченні прогони з фіксованим seed, без підміни аналітичним результатом.

Ці дані демонструють чутливість методу, але не доводять порівнянності оцінок, команди чи умов з нашим проєктом. Їх не додаємо до velocity.csv/forecast.csv та не використовуємо як заміну двом власним спринтам.
